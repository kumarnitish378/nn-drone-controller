# NN flight control for ArduPilot (C++)

This folder holds the trained quad and hex networks as a C++ library for ArduPilot. It includes a Copter flight
mode that hands the motors to the network.

| Path | What it is | ArduPilot dependency |
|---|---|---|
| `libraries/AP_NNControl/NN_*` | Portable core. It builds the network inputs, keeps the history frames and the position-error integral, and runs the network. | none (C++11, no heap) |
| `libraries/AP_NNControl/models/` | Weights of the shipped networks, generated by `python -m nn_drone export-cpp` | none |
| `libraries/AP_NNControl/AP_NNControl.*` | `NN_*` parameters. It reads AHRS, INS and battery, and logs to `NNC`. | AP_AHRS, AP_InertialSensor, AP_BattMonitor, AP_Param, AP_Logger |
| `libraries/AP_NNControl/AP_MotorsMatrix_NN.*` | `AP_MotorsMatrix` that uses the network's PWM while the motors are at full authority | AP_Motors, SRV_Channel |
| `libraries/AP_NNControl/copter_mode/mode_nn.*.in` | **NN** flight mode, to copy into `ArduCopter/`. The sticks move a target and the network flies to it. | ArduCopter |
| `libraries/AP_NNControl/INTEGRATION_PROMPT.md` | Instructions for a coding agent to wire the library into an ArduPilot tree | |
| `tests/` | Host test: replays Python flights through the core and checks the tanh backends | none |

## What has been checked, and what has not

- **The core matches the Python network.** `tests/test_cpp_library.py` records 15 s Python flights at 400 Hz:
  disarmed, idle, spool-up, take-off and the start of a waypoint leg. The flights are a 1 kg and a 4 kg quad and
  a 95 kg hexacopter. Each step is replayed through `NN_Pilot`. Results:
  - Inputs agree to 7.5e-7. Motor commands agree to 2.4e-7 with the C library's tanh and 6e-7 with the fast
    tanh, which is 0.0003 µs of PWM.
  - The test runs in CI and also checks that the model headers match the shipped `.npz` files.
- **The CORDIC code was checked against an emulated peripheral, not on silicon.** The emulation lets the
  library's scaling, range reduction and q1.31 handling be tested on a PC (`tests/fake_stm32_cordic.h`).
  - Error against tanh: 5e-8.
  - On real hardware with 24 iterations, expect about 1e-6.
- **The ArduPilot files were only checked against stubs of the APIs they use. They have not been built inside an
  ArduPilot tree.**
  - `AP_NNControl.cpp` was compiled against those stubs.
  - `AP_MotorsMatrix_NN` and `mode_nn` follow the ArduPilot 4.5/4.6 APIs but were not compiled.
  - ArduPilot renames things between releases, so expect small fixes when you build it.
- **Nothing has flown on a real vehicle.**

## Adding it to ArduPilot (Copter)

**With a coding agent:** copy `libraries/AP_NNControl/` into `ardupilot/libraries/`. Then tell the agent, from the
ArduPilot checkout: *"Read libraries/AP_NNControl/INTEGRATION_PROMPT.md and implement it."*

**By hand:**

1. Copy `libraries/AP_NNControl/` into `ardupilot/libraries/`. Copy `copter_mode/mode_nn.h.in` and
   `copter_mode/mode_nn.cpp.in` to `ardupilot/ArduCopter/mode_nn.h` and `mode_nn.cpp`.
2. `ArduCopter/wscript`: add `'AP_NNControl',` to `ap_libraries`.
3. `ArduCopter/config.h`:
   ```cpp
   #ifndef MODE_NN_ENABLED
   #define MODE_NN_ENABLED 1
   #endif
   ```
4. `ArduCopter/mode.h`: add `NN = 40,` to `enum class Number` (any free number), and `#include "mode_nn.h"` at the
   end of the file.
5. `ArduCopter/Copter.h`:
   ```cpp
   #include <AP_NNControl/AP_NNControl.h>
   #include <AP_NNControl/AP_MotorsMatrix_NN.h>
   // in class Copter:
   AP_MotorsMatrix_NN *motors_nn = nullptr;
   #if MODE_NN_ENABLED
   ModeNN mode_nn;
   #endif
   friend class ModeNN;
   ```
6. `ArduCopter/mode.cpp`, in `Copter::mode_from_mode_num()`:
   ```cpp
   #if MODE_NN_ENABLED
       case Mode::Number::NN:
           ret = &mode_nn;
           break;
   #endif
   ```
7. `ArduCopter/Parameters.h`: add `AP_NNControl nn_control;` to `ParametersG2`. In `Parameters.cpp`, add it to
   `ParametersG2::var_info` with the next free index:
   ```cpp
   AP_SUBGROUPINFO(nn_control, "NN_", <next index>, ParametersG2, AP_NNControl),
   ```
8. `ArduCopter/system.cpp`, in `allocate_motors()`: for `MOTOR_FRAME_QUAD` and `MOTOR_FRAME_HEXA`, create the NN
   motors instead of `AP_MotorsMatrix`. Use the same constructor arguments your version passes to
   `AP_MotorsMatrix`:
   ```cpp
   motors_nn = NEW_NOTHROW AP_MotorsMatrix_NN(copter.scheduler.get_loop_rate_hz());
   motors = motors_nn;
   motors_var_info = AP_MotorsMatrix::var_info;
   ```
9. Pre-arm, in `AP_Arming_Copter::parameter_checks()`:
   ```cpp
   char failure[50];
   if (!copter.g2.nn_control.pre_arm_check(failure, sizeof(failure))) {
       check_failed(ARMING_CHECK_PARAMETERS, display_failure, "%s", failure);
       return false;
   }
   ```

Then build as usual: `./waf configure --board <your H7 board> && ./waf copter`. For SITL, use `--board sitl`.

### Parameters

| Parameter | Value | Why |
|---|---|---|
| `SCHED_LOOP_RATE` | 400 | The networks were trained for a 400 Hz loop. The mode refuses to start at another rate. |
| `MOT_PWM_MIN` / `MOT_PWM_MAX` | 1000 / 2000 | The network's PWM maps linearly to throttle over 1000–2000 µs. |
| `NN_ENABLE` | 1 | |
| `NN_MASS` | take-off mass, kg | The network scales lengths by ∛mass and times by the square root of that. It was tested from 1 to 100 kg. |
| `NN_BATT_CELLS` | cells in series | The network was trained on a 4S pack. Other packs are rescaled to 4S volts. |
| `NN_ERR_CLIP` | 2.5 | How far away the target is ever shown, in metres ÷ ∛mass. 2.5 is what the networks were tested with. |
| `NN_TANH` | 0, 1 or 2 | 0 is the C library, 1 is the fast FPU approximation, 2 is CORDIC (see below). |
| `NN_LOG` | 1 | Logs `NNC` every loop: update time in µs, integral, and PWM per motor. |
| `FLTMODEx` | 40 | Selects the NN mode (or the number you chose). |

### Flying it

- **Arming:** arm in NN mode. ArduPilot spools the motors up as usual, and the network takes over once they
  reach full authority.
- **Sticks:**
  - Pitch and roll move the target at `WPNAV_SPEED`.
  - Throttle above or below centre raises or lowers it at `WPNAV_SPEED_UP` / `WPNAV_SPEED_DN`.
  - Yaw turns the target heading at up to 90°/s.
  - The target is never more than `NN_ERR_CLIP × ∛mass` metres ahead, so the drone stops close by when you let
    go.
- **Landing:** switch to LAND or another mode, and ArduPilot's own controllers take over.
- **Network continuity:** the network runs every loop from arming, also during spool-up, so its history and
  its record of the previous motor commands stay continuous, as in training.

## STM32H7 and the hardware accelerators

A network update is the three dense layers plus the input building:
- Quad: 8,256 multiply-adds and 132 tanh.
- Hex: 8,768 multiply-adds and 134 tanh.
- Weights: 33.6 kB per frame (quad) and 35.6 kB (hex), float32.

A 480 MHz Cortex-M7 with its FPU should need a few tens of microseconds, which is about 1–2 % of a 2.5 ms
loop. That's an estimate, not a measurement: read `NNC.Us` in the log for the real figure on your board.

| Option | How to turn it on | What it does |
|---|---|---|
| Portable kernel (default) | — | Four independent sums per neuron, so GCC can issue the M7's `VFMA` back to back. Weight rows are contiguous and 32-byte aligned (one cache line). |
| CMSIS-DSP | build with `NN_USE_CMSIS_DSP=1` | `arm_mat_vec_mult_f32` for the dense layers. Needs CMSIS-DSP on the include path. ArduPilot's ChibiOS boards with `HAL_WITH_DSP` already link it for the gyro FFT. |
| Fast tanh | `NN_TANH 1` | [9/8] Padé approximant: 8 multiply-adds and one divide on the FPU, error under 7e-6. On the host it made the whole update 2–3× faster than the C library's `tanhf`. |
| CORDIC tanh | build with `NN_USE_STM32_CORDIC=1`, then `NN_TANH 2` | Computes cosh and sinh on the CORDIC co-processor, with tanh = sinh/cosh. **Only STM32H723/725/730/733/735 have a CORDIC; H743/H750/H753/H757 do not.** The CPU waits for each result, so expect it to be about as fast as the fast tanh. It's worth it only if you need the FPU for something else at the same time. |
| Weights in DTCM | build with `NN_WEIGHTS_SECTION='__attribute__((section(".dtcm")))'` (or your linker script's section name) | Single-cycle weight reads instead of flash through the cache. Uses about 34 kB of DTCM per frame built in. |
| One frame only | build with `NN_WITH_HEX_X=0` or `NN_WITH_QUAD_X=0` | Saves about 34 kB of flash. |

The FMAC unit on H72x/H73x is meant for FIR/IIR filters in q15 fixed point, so it doesn't help a float network.
A large speed-up would need an int8 network (CMSIS-NN), and that means quantising the weights and checking
again that it still flies. It's not needed at these timings.

## Things to know before flying

- **The networks were trained only in simulation.** The simulated drone has:
  - thrust/weight 2.8;
  - thrust ∝ throttle² × (V / 16 V)²;
  - a motor time constant of 50 ms × mass^(1/6);
  - a 4S battery.

  A vehicle far from that will fly worse. For example, the network expects hover near 1600 µs at 16 V. The
  integral input absorbs small differences.
- **The network's command reaches the motors one loop later than in training.** ArduPilot writes the motors at
  the start of each loop, and the mode runs at its end. At 400 Hz that's 2.5 ms, against a 50 ms motor time
  constant.
- **Test in SITL first.** SITL's default copter does not match the training airframe. Expect it to fly, but less
  well than in this project's simulator.
- **Lowering the loop rate is not supported.** The model refuses to run at anything but 400 Hz.
